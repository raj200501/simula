Daily Reader Streak & Ad-Free Access

Trigger

Users interact with the Daily Streak card in the Account Sidebar (s11) to earn credits, or tap 'Go Ad-Free' in Article Details (s03) to redeem credits for ad-free reading.

Eligibility

Non-signed-in users and signed-in non-subscribers who have not claimed today's reward.

What the user sees

Earn News Credits Play a 15-second game with AOL to earn 10 News Credits, or unlock 15m of Ad-Free reading!
Play Now No thanks

Reward and caps

10 News Credits; granted on REWARD_VERIFIED. At most 3 a day, 30 min apart.

Integration (@simula/ads-react-native)

import { SimulaAds, useRewardedAd, MiniGameButton } from "@simula/ads-react-native";
import { useEffect, useState } from "react";

// P3 on "Account Menu Sidebar". Trigger: Users interact with the Daily Streak card in the Account Sidebar (s11) to earn credits,…
// Caps 3/day, 30 min apart: app remote config (unit cap: dashboard)
const AD_UNIT = "SIM-RWD-account-menu-sidebar"; // placeholder: create it in the dashboard

export function DailyReaderStreakOffer({ userId, partnerImageUrl, grant, onDecline }) {
  const rwd = useRewardedAd(AD_UNIT);
  const [capped, setCapped] = useState(true);
  useEffect(() => {
    SimulaAds.checkFrequencyCap(AD_UNIT, userId).then(setCapped); // true: hide
    rwd.setMetadata({ surface: "account-menu-sidebar", proposal: "P3" });
    rwd.load({ charName: "AOL" }); // Game Partner
  }, [userId]);
  useEffect(() => {
    // Grant on REWARD_VERIFIED (server-verified), never on EARNED_REWARD.
    if (rwd.rewardVerified) grant({ amount: 10, resource: "News Credits", token: rwd.rewardToken });
  }, [rwd.rewardVerified]);
  // no_fill or not loaded: render nothing; today's path is unchanged.
  if (capped || !rwd.isLoaded || rwd.error?.code === "no_fill") return null;
  // "No thanks" stays the app's own control: back to where the user was.
  return (
    <MiniGameButton
      text={"Play Now"}
      onClick={() => rwd.show()}
    />
  );
}
// Min play 15s is a unit setting (no RN load option; unverified).
// Needs <SimulaProvider apiKey={...}> at the root; grant() is your server call.

Method and mock fidelity

  1. Explore. 60 steps, 17 states, 58 edges, 1 external surface in 8 min; stopped: budget steps. 72 actions deliberately not explored.
  2. Understand. 17 screens in the product model; 8 claims verified against on-screen text, 0 inferred. Synthesized by llm.
  3. Mock + QA. 33% of screens rebuilt in HTML; 22/22 navigation flows pass.
  4. Propose. 8 ideas, 3 developed into typed proposals (patch, storyboard, assumptions). Generated by llm.
  5. Judge. 6 judgment rounds for 3 proposals: code gates first, then a rubric scored by llm; the verdict is computed in code (ship ≥ 3.8, every criterion ≥ 3, ≤ 2 rounds).
  6. Slides. Every frame is a screenshot of the patched mock driven through its runtime API; callouts sit on measured DOM positions; numbers come from economics code.

AOL · Appendix

How this runs across hundreds of apps

Storage and versioning

  • Screenshots, element lists and HTML are content-addressed blobs; artifact JSON references them by hash.
  • A model version is keyed by package, version code and a UI fingerprint of the core flows, which also catches over-the-air updates.
  • A diff between two model versions (screens, walls, prices, offers) is itself a sales signal.

When to re-explore

  • Daily store version poll; weekly no-LLM smoke replay of the core flows and the path to the wall.
  • Drift above 10% or any price change triggers an incremental re-explore from the known graph (about 20% of first-run cost).
  • A new ad format re-runs only propose and judge.

Where humans review

  • App onboarding and login (15 min); economy review, the highest-leverage step (10 min).
  • Deck approval before any customer sees it (15–30 min); exception queue for blocked apps.
  • Monthly judge audit against labelled outcomes.

Cost and sales fit

  • Prospect scan without a mock ≈ $5 of model calls; full pitch pack ≈ $20–25 plus 45–60 min of human review.
  • The deck, clickable prototype and sizing sheet attach to the CRM deal; each SHIP's integration snippet becomes the implementation ticket.
  • Post-launch opt-in, completion and IAP guardrails flow back to recalibrate economics and the judge.
